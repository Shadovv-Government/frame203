# FRAME — совместная сверка разметки

## Установка

Распакуйте **содержимое этой папки** в корень вашего репозитория: рядом с существующими `src`, `data`, `labeling`. В архиве только новые файлы приложения. Исходные скрипты, фотографии, JSON и готовые решения не включены и не заменяются.

```text
ваш-проект/
├── START_REVIEW.cmd
├── README_REVIEW.md
└── src/
    ├── review_app.py
    └── review_ui/
        ├── review.html
        ├── style.css
        └── app.js
```

## Запуск

Дважды нажмите `START_REVIEW.cmd` или выполните из корня проекта:

```powershell
python src/review_app.py
```

Для существующего виртуального окружения:

```powershell
.\.venv\Scripts\python.exe src/review_app.py
```

Нужен Python 3.10+. Дополнительные пакеты и Streamlit не нужны: сервер раздаёт только статический интерфейс. Если порт занят, добавьте `--port 8766`.

Откройте **Chrome или Edge** по адресу `http://127.0.0.1:8765/review.html`, нажмите **«Открыть папку проекта»**, выберите корень вашего репозитория и разрешите чтение/запись. Если автоматически открылся другой браузер, скопируйте адрес в Chrome/Edge. Выбор папки с прямой записью доступен не во всех браузерах: https://developer.mozilla.org/en-US/docs/Web/API/Window/showDirectoryPicker .

Сервер доступен только на этом компьютере (`127.0.0.1`) и раздаёт только папку интерфейса. Данные читаются браузером после выбора папки. Приложение не загружает SMS и фото в интернет. Единственный внешний ресурс — необязательный шрифт Google Fonts; офлайн включается системный шрифт.

## Входные файлы

- `reports/agreement/sms_items.csv`
- `reports/agreement/cars_items.csv`
- `labeling/resolution/sms_resolution.csv`, если уже есть
- `labeling/resolution/cars_resolution.csv`, если уже есть
- `data/interim/car_enrichment/car_enrichment_manifest.csv` — имена фото
- `data/processed/images_new_v1/car_new_XXXX.jpg` — фотографии
- `labeling/exports/pilot/A_cars.json`, `B_cars.json` — необязательные комментарии к пилотным фото; читаются без изменения, если покрывают ID отчёта

Достаточно отчёта по одному типу данных. Отсутствующая таблица сверки создаётся при сохранении первого решения. Если отчётов нет, сначала получите оба экспорта и выполните существующий скрипт:

```powershell
python src/agreement.py sms --a labeling/exports/pilot/A_sms.json --b labeling/exports/pilot/B_sms.json
python src/agreement.py cars --a labeling/exports/pilot/A_cars.json --b labeling/exports/pilot/B_cars.json
```

Само приложение расчёт согласия не запускает. Для `agreement.py` нужны зависимости вашего проекта.

## Как выбирать

1. Откройте SMS или машины. **A — Кирилл, B — Григорий.**
2. По умолчанию видны расхождения и сомнительные случаи. Для машин проверяются также разные атрибуты и `uncertain`, даже если их не было в старом шаблоне сверки.
3. SMS: прочитайте текст, примите A/B или задайте итоговую метку и подтип.
4. Машины: смотрите рамки рядом, наложенными или исходное фото. Текущая рамка яркая, остальные приглушены. Масштаб общий, прокрутка синхронизирована. Кнопка «К выбранной рамке» увеличивает область.
5. Выберите A/B для конкретной рамки или «Убрать рамку». Добавьте причину и нажмите «Сохранить и дальше».
6. Решение записывается в `labeling/resolution/`. Перед каждой перезаписью старый CSV копируется в `labeling/resolution/backups/`.
7. Фильтр «Непросмотренные спорные» показывает остаток; прогресс относится к текущему виду данных.

В одной фотографии точнее могут быть разные участники для разных машин. Если две одиночные строки (`only_A` и `only_B`) относятся к одной машине, оставьте лучшую, другую уберите после визуальной проверки. Новые рамки и ручное изменение координат здесь не поддерживаются — такие случаи исправляются отдельно.

### Важное ограничение атрибутов

Существующий `build_gold.py` выбирает **координаты** A/B через поле `use`. Атрибуты сопоставленной пары он объединяет (логическое ИЛИ), а не берёт у выбранного аннотатора. Приложение это правило не меняет и показывает предупреждение. Чтобы убрать ошибочный атрибут из итоговой рамки, потребуется отдельно изменить сборщик/формат решений.

## Что сохраняется

CSV дополняются `reviewed` и `reviewed_at`. Ваш `build_gold.py` эти дополнительные поля игнорирует. Заполненные ранее gold-поля без `reviewed=1` показываются как ещё не просмотренные: некоторые поля исходного шаблона заполнялись автоматически. Прежние решения и дополнительные столбцы сохраняются.

Исходные `A_*.json`, `B_*.json`, отчёты согласия и фотографии **не меняются**. После перезапуска откройте папку проекта снова — сохранённые решения загрузятся из CSV.

Работайте **в одной вкладке за одним компьютером**. Это не многопользовательский сервер. Если файл поменялся после загрузки, запись блокируется, чтобы не затереть чужую работу. Проверка не является транзакционной блокировкой: одновременное редактирование запрещено. Не подменяйте отчёты и не перезапускайте `agreement.py` во время сверки: `pair_id` зависит от порядка строк, а не является постоянным ID машины. Если CSV открыт в Excel, закройте Excel перед сохранением.

Файлы отчётов не содержат этап в названии. Убедитесь, что отчёты, таблицы сверки и экспорты относятся к одному набору (`pilot` или `main`).

## Если браузер не даёт записывать

«Открыть папку только для чтения» → выберите корень проекта. Решения остаются **в памяти вкладки**. Нажмите «Скачать таблицы сверки», разрешите несколько загрузок, проверьте наличие обоих CSV и перенесите их в `labeling/resolution/`, предварительно скопировав прежние файлы. Не закрывайте страницу до скачивания. Рекомендуемый режим — прямая запись через Chrome/Edge.

## После сверки

Проверьте, что все спорные случаи просмотрены, и выполните:

```powershell
python src/build_gold.py sms --tag pilot
python src/build_gold.py cars --tag pilot
```

Gold автоматически не строится. Независимые метрики согласия не пересчитываются после совместных решений.

У приложения нет исключения целой фотографии; также в `cars_items.csv` нет строк для фотографий, где у обоих аннотаторов ноль рамок. Такие кадры проверьте отдельно по исходным экспортам/списку задач.
